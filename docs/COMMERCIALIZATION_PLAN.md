# Commercialization Plan

## Scope

This project is moving from a local Vite/React OA prototype to a commercially acceptable internal OA system. The commercial cut must preserve the current business intent while replacing local mock state with durable backend persistence, authenticated access, backend-enforced RBAC, workflow snapshots, append-only audit logs, and repeatable deployment operations.

The product must not copy Feishu branding, trademarks, proprietary copy, logos, icons, screenshots, color identity, or protected visual assets. The acceptable direction is a business-equivalent HR/Admin OA system with original product naming, original UI assets, and implementation-owned copy.

## RPO / RTO

Production targets:

- RPO: <= 24h. At least one successful database backup and one successful file-storage backup must exist for every production day.
- RTO: <= 4h. A fresh database restore, file-storage restore, migration check, app/API boot, and smoke verification must complete within four hours.
- Backup frequency: nightly scheduled database and file-storage backup plus a manual backup before schema migrations, bulk imports, attachment migrations, or risky data repair.
- Backup retention: keep at least the 14 newest local database and file-storage backups through `npm run prune:backups`; production owners should additionally keep 7 daily, 4 weekly, and 3 monthly off-host copies unless a stricter policy is set.
- Restore drill: run at least one restore drill before commercial acceptance and repeat monthly for production.

## Migration And Rollback Boundaries

Prisma or SQL migrations are not assumed automatically reversible.

- Before every production `db:deploy`, run `npm run validate:migrations -- --json` and confirm `prisma/migrations/migration-lock.json` still matches the reviewed migration history. If a new migration was intentionally added, regenerate the lock with `npm run migrations:lock -- --json` only after review.
- Before every production migration, run `npm run backup:postgres` and `npm run backup:files`, then record both backup paths, checksums, migration version, and app image/tag.
- Low-risk additive migrations can roll forward with a compatible app rollback.
- Destructive migrations, column type changes, data rewrites, and enum changes require a written forward-fix plan and restore point.
- If a migrated app fails but the schema remains backward compatible, roll back the app image first.
- If schema or data is incompatible, restore the database from the pre-migration backup into a fresh database or volume; do not partially hand-edit production rows without an incident note.
- Object storage and uploaded source files need their own backup policy. The backend now routes attachments and imported HTML source artifacts through a storage adapter: `FILE_STORAGE_DRIVER=local` stores under `FILE_STORAGE_DIR`, while `FILE_STORAGE_DRIVER=s3` uses a S3-compatible endpoint with AWS Signature V4 requests. Local-volume deployments still need `npm run backup:files` / `npm run restore:files -- <file-storage-backup.tar.gz> --yes` or an equivalent platform restore. Object-storage deployments must prove bucket backup/replication and restored download smoke in signoff evidence. A database restore alone is not sufficient if audit rows reference missing attachments. Close GAP-004 only after `docs/file-storage-signoff.example.json` has been replaced with reviewed production evidence and `npm run validate:storage-signoff -- <signoff.json> --environment production --json` passes.

## Data And Compliance Boundary

The commercial product must treat these as controlled data:

- Personnel identity, phone, address, education, salary, leave, and employment status.
- Approval form payloads and comments.
- Export files and export filters.
- Audit payloads, failed-login metadata, and source IPs.
- Request IDs that connect API responses, logs, and audit metadata.
- Source-lineage files and source checksums imported from legacy dashboards or spreadsheets.

Sensitive values should use a single redaction policy in the backend so API responses, audit payloads, exports, and logs do not diverge.
