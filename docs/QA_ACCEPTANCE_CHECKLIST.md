# QA Acceptance Checklist

Use this checklist for the first commercial cut and every release candidate that touches auth, workflow, exports, audit, backup, restore, or schema migrations.

| Area | Acceptance Check | Evidence |
| --- | --- | --- |
| App load | App opens on the target URL, first meaningful screen renders, and no framework error overlay is visible. | Playwright screenshot or manual screenshot. |
| Global search | The top search box returns clickable menu, application, workflow, personnel, approval, asset, resource, booking, and audit entries from the current frontend state; workflow entries open the correct launch form, module entries navigate to the target page, resource/audit entries navigate without clearing unrelated state, and sensitive personnel fields such as phone/address/ID/bank/salary are neither indexed nor exposed in search results. Desktop and mobile search overlays must not create horizontal overflow. | `src/services/globalSearch.js`, frontend global-search unit tests, Playwright global-search smoke, and desktop/mobile screenshot evidence. |
| Runtime readiness | `/health` returns process liveness, `/ready` returns PostgreSQL, live append-only database trigger integrity, and file-storage readiness before traffic is routed, and authenticated admins can view `/api/system/readiness` plus the audit-page 商用发布状态、证据工件清单 and 发布闭环清单 panels without exposing secrets, origins, HR review package paths, signoff draft paths, gap-report paths, latest evidence paths, artifact paths, checksums, validation commands, blocker details, database URLs, or filesystem paths. | API response, backend readiness tests, system readiness tests, Playwright audit panel check, and compose healthcheck. |
| API contract | `/api/openapi.json` exposes the commercial API contract; `docs/openapi.json` is generated from the same source and checked before verification continues. | `/api/openapi.json`, `docs/API_CONTRACT.md`, `docs/openapi.json`, `npm run contract:api`, backend OpenAPI test, and preflight check. |
| Runtime secrets | Production refuses placeholder JWT secrets, wildcard, HTTP, local, or template CORS origins, weak/default/placeholder seed admin passwords, unapproved production seed runs, relative or temporary local-volume file storage, insecure object-storage endpoints, and incomplete object-storage settings. | Config tests, seed-safety tests, and deployment env review. |
| Commercial env template | `.env.example` is usable for the local Docker commercial stack, keeps frontend API-required mode enabled, includes nginx `8080` and Vite dev origins in `WEB_ORIGIN`, and does not commit the production placeholder JWT secret as the demo value. | Preflight `.env.example` checks and deployment runbook review. |
| Login skeleton/session | Current user/session affordance is visible; commercial backend exposes `/api/auth/me` before release. | Playwright smoke plus API response. |
| Session revocation | Logout increments the user session version so the old JWT/cookie is rejected by protected APIs. | Backend auth test and commercial smoke logout check. |
| Session cookie | Login sets an explicit-lifetime `HttpOnly` `SameSite=Lax` cookie; production cookies are `Secure`; logout clears the same cookie attributes. | Backend cookie header tests, production config validation, and preflight check. |
| Login protection | Failed login attempts return generic errors, write audit rows for valid tenants, repeated attempts return `429` with `Retry-After`, and in-memory failure buckets are capped to avoid unbounded growth under account-spraying load. | Backend auth negative tests, bounded-store test, config validation, and audit rows. |
| Origin protection | Cross-site browser `POST`/`PUT`/`PATCH`/`DELETE` requests with untrusted `Origin` or `Referer` are rejected before mutating data; trusted web origins and no-origin automation remain usable; spoofed `X-Forwarded-*` headers are ignored unless `TRUST_PROXY=1` is explicitly enabled behind a trusted reverse proxy. | Backend CSRF origin guard/proxy-spoof tests and deployment `WEB_ORIGIN` / `TRUST_PROXY` review. |
| API security headers | API responses carry `X-Request-Id`, hardening headers, `/api/*` no-store cache control, production HSTS, and audit metadata stores the request id for traceability. | Backend header test, audit metadata test, and preflight check. |
| API fallback guard | Production or `VITE_REQUIRE_API=1` builds do not silently show local demo data when the API is unavailable. | Frontend policy test, Docker web build-arg test, and deployment env review. |
| Production deployment guard | Production Compose requires real PostgreSQL password, JWT secret, and web origin values, defaults `RUN_DB_SEED=0` and `ALLOW_PRODUCTION_SEED=0`, avoids host PostgreSQL exposure, runs the API image as a non-root user with a prepared writable storage path, applies `no-new-privileges` and drops all Linux capabilities for the API service, blocks unapproved production seed, and keeps non-example `.env.*` files out of Docker build context. | `Dockerfile.api`, `docker-compose.prod.yml`, `.env.production.example`, `.dockerignore`, deployment runbook, seed-safety tests, image-security tests, and preflight check. |
| Production env file validation | A real `.env.production` file is checked before deployment and rejects template secrets, example domains, local origins including IPv4 and IPv6 loopback addresses, relative local-volume paths, unsafe backup directories, incomplete S3-compatible object-storage settings, weak body limits, demo fallback, and unapproved production seed settings. | `npm run validate:production-env -- .env.production --json`, production-env validator tests, deployment runbook, and preflight check. |
| Migration integrity lock | Every committed Prisma `migration.sql` is pinned by path, byte size, statement count, and SHA-256 before commercial CI, release evidence, and production deployment. Historical migration drift fails closed; lock updates are allowed only after intentional migration review. | `npm run validate:migrations -- --json`, `npm run migrations:lock -- --json`, `prisma/migrations/migration-lock.json`, migration-lock unit tests, preflight check, CI gate, and release evidence. |
| Dependency supply chain | The committed package lock must use lockfile v3, include every declared dependency, keep package integrity hashes, resolve packages from the npm registry over HTTPS, and stay within the approved permissive license allow-list. | `npm run validate:supply-chain -- --json`, supply-chain unit tests, preflight check, CI gate, and release evidence. |
| SBOM artifact | A machine-readable SPDX SBOM is generated from the committed package lock, reports a stable source hash plus exact document hash, is written as a private release artifact, and is included in release evidence before acceptance. | `npm run sbom:generate -- --json`, `npm run sbom:generate -- --check --json`, SBOM unit tests, preflight check, CI gate, and release evidence. |
